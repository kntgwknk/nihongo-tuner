## 何をするスキルか

日本語の文章を、読みやすく自然な文章に直す。直すのは文の書き方と組み立てで、**書かれている事実は変えない**。

読みやすさの土台は日本語の文の組み立て方にある。主題をどこで立てるか、修飾語をどの順に並べるか、どこで読点を打つか、動作を動詞で書くか名詞にまとめるか。AIが書いた文章の癖を消しても、この土台が崩れていれば読みにくいままである。そこで、基礎（`japanese-basics.md`）と癖（`surface-patterns.md`）の両方を見る。

AIが書いた文章は、定型の空句（「重要なのは」「包括的」など）よりも、太字・括弧・ダッシュの多用、決め台詞、結論を段落の最後に置く説明調の組み立てで見分けられることが多い。作者がAIに書かせた業務資料26本を数えたところ、空句は0件だったが、太字が1,241箇所、括弧書きが2,457箇所、ダッシュが179箇所あった。

## 参照（必要になったところで読む）

1. `references/japanese-basics.md`：日本語のしくみと読みやすさ。文の中で結び付く語の組ごとに、R1主題と述語、R2述語と補語、R3修飾、R4呼応と並列、R5前後の文、R6文末と確信、R7語の選び方と表記、R8文の長さと論点の数に分けて、点検の問いを置いている。
2. `references/genres.md`：ジャンルごとの文末・結論の位置・語り口の許容範囲と、直し方の当てはめ方
3. `references/surface-patterns.md`：AIの書き癖と翻訳調の一覧と直し方。読点の打ち方は §11、縮めすぎた表現は §14、英数字の前後の空白は §15。
4. `references/structure-patterns.md`：結論先行とグループ化の型と、直しすぎないための決まり
5. `references/do-not-change.md`：変えてはいけないもの（事実・識別子・画面文言・コードブロック・確信の度合い）と境界事例
6. `references/delegation-template.md`：複数ファイルをサブエージェントに分担するときの依頼文の雛形

スキルのフォルダに `local.md` があれば、手順に入る前に読んで従う。使う環境ごとの決まり（対象から外すファイル、ほかのスキルとの使い分けなど）を書くためのファイルで、配布する版には入れない。本文と食い違うときは `local.md` を優先する。

## 手順

### 1. 対象範囲を決める

- 対象ファイルを一覧にする。ディレクトリ指定なら `.md` と `.txt` を列挙し、作業ログ・計画ファイル・退避フォルダ・自動生成ファイル・コードは外す。
- gitで管理しているなら `git status` を見て、他の人や別の作業が未コミットの編集を持っているファイルを対象から外す。外したファイルは最後の報告に書く。
- 書き換え前の版を残す。gitなら作業ブランチを切る。gitでなければ元のファイルを別の場所に写しておく（手順7の照合の基準になる）。

### 2. ジャンルと読み手を決める

`references/genres.md` の表から、対象のジャンル（業務文書・技術文書・記事・エッセイ・メール）を決める。誰が読み、読んだあと何をしてほしい文章かも確かめる。分からなければ書き手に聞く。ジャンルで、文末・結論の位置・どこまで癖を直すかが変わる。

### 3. 書き癖を数える

```bash
python scripts/measure_style.py <ファイル...>
```

太字・括弧・ダッシュ・矢印・絵文字・決め台詞・空句・開発者の言葉・打ち消し・冗長な言い回し・文末の混在・読点の偏り（読点が4つ以上ある文、読点と読点のあいだが短い文、短い文で主語の直後に読点がある文、50字以上で読点のない文）・和文と英数字のあいだの空白を、ファイル別と合計で数える。`--list` を付けると、読点の偏りがある文と、空白の入った箇所を一覧で出す。数値は手順6で使うので控えておく。Python 3.10以上の標準ライブラリだけで動く。

### 4. 見本を作り、了承をもらう

- 代表的な1本から4〜6箇所を選び、修正前と修正後を並べて見せる。基礎の直し（`japanese-basics.md`）、癖の直し（`surface-patterns.md`）、組み立ての直し（`structure-patterns.md`）を混ぜる。
- 直し方の方針（文末、太字をどこまで残すか、変えないもの、ジャンルとして残す語り口）を箇条書きで添える。
- **人に渡す文章や公開する文章は、了承を得るまでファイルを書き換えない。**

### 5. 書き換える

次の順で見る。前のものほど、読み手の負担が大きい。

1. 文の組み立て：`japanese-basics.md` のR1〜R6の問いを、R1（主題と述語）、R2（述語と補語）、R3（修飾）、R4（呼応と並列）、R5（前後の文）、R6（文末と確信）の順に当てる。R8（文の長さと論点の数）もここで見る
2. 語の選び方：`japanese-basics.md` のR7と、比喩や直訳でぼかした言い回し、縮めすぎた表現と中身のぼやけた動詞（`surface-patterns.md` §6・§13・§14）
3. 表面の癖：太字・括弧・ダッシュ・決め台詞・打ち消し・絵文字・矢印・英数字の前後の空白（`surface-patterns.md`）
4. 組み立て：結論の位置とグループ化。ジャンルが許す範囲で、直しすぎない（`structure-patterns.md`）。

どの段階でも、直すのは理由を言える箇所だけにする（`do-not-change.md` §8）。より自然そうに見える言葉への言い換えは、理由がなければしない。

直しても不自然さが残る箇所では、語の置き換えを繰り返さない。その箇所で読み手に何を伝えたいかを1文で言い、そこから組み立て直す。短くして意味が伝わらなくなったら、必要な言葉を戻す（`surface-patterns.md` §14）。

言い換えるときも組み立て直すときも、元の文にない条件・理由・様子・程度を足さない。意味が1通りに決まらない語・比喩・標語は、読み方を自分で選んで書き換えず、元の語のまま残して書き手に聞く（`do-not-change.md` §7）。

ファイルが4本以上なら、サブエージェントに分担してよい。`references/delegation-template.md` の雛形を使い、**1ファイルを担当するのは1エージェントだけ**にする。見本で了承を得た修正前後の例を、依頼文にそのまま入れる。

### 6. もう一度数え、目標に届かないものは2巡目をかける

手順3と同じスクリプトを流し、次の目標と比べる。業務文書と技術文書の値である。記事とエッセイでの扱いは `genres.md` にある。

| 指標 | 目標 |
| --- | --- |
| 文の括弧（表の外で、中身が文になっている括弧） | 各ファイル0〜2 |
| 太字過多の節（表の外で太字が3つ以上ある節） | 0 |
| 決め台詞・空句・開発者の言葉・絵文字・ダッシュ・冗長 | 0（残すなら1件ずつ理由を言える状態にする）。文の主題や述語として主張を担っている空句は残し、0に数えない（`surface-patterns.md` §9） |
| 読点過多文（読点が4つ以上ある文） | 0。読点を減らすために、文を分けるか語順を直す。名詞を並べただけの読点は数えなくてよい |
| 読点が細かい文（読点と読点のあいだが平均12字未満） | 0。主語や接続詞ごとに打った読点を消す |
| 短い文の主語読点（30字以下の文で、15字未満の主語・主題の直後にある読点） | 0。主語と述語のあいだの読点を消す。文頭の接続詞のあとのほうが大きい切れ目なら、読点をそちらへ移す。同じ語が続いて読みにくくなる所は残してよい |
| 句点の落ちた項目（途中に句点があるか、です・ます で終わるのに、句点で終わらない箇条書きの項目。同じ一覧に句点で終わる項目があれば、だ・である調の1文の項目も数える。番号付きの箇条書きも同じ） | 0。最後の文にも句点を付ける（`surface-patterns.md` §8） |
| 英数字の前後の空白（和文と半角英数字のあいだの半角の空白） | 0。空白だけを消す。書き手や媒体の表記の決まりで入れているときは数えない（`surface-patterns.md` §15） |
| 読点なし長文（50字以上で読点のない文） | 目標値は置かない。係り方が2通りに読める文だけ直し、読点を足す前に文を分けるか語順を直す |
| 打ち消し（「ではなく」「わけではない」） | 目標値は置かない。1件ずつ `surface-patterns.md` §12の扱い方で残すか決める |

太字の総数そのものは目標にしない。0も目標にしない。残すのは `surface-patterns.md` §1の対象（操作を誤ると処理が止まる注意、取り違えやすい否定）に当たる箇所だけで、1節に1〜2箇所までにする。当たる箇所がなければ0でよい。

変えてはいけないもの（`do-not-change.md`）は計測の目標値より優先する。目標に届かせるために、主張を変えたり、元の文にない内容を足したり、同じ意味の語に置き換えたりしない。

数値は癖を拾う目安で、読みやすさそのものではない。数値が目標に届いても、`japanese-basics.md` の観点で読み直す。届かなかったファイルには2巡目をかける。依頼にはファイルごとの現在値と目標値、修正前後の例を書く。「括弧の補足を減らす」のような指示だけでは解釈がぶれ、作者の実測では1巡目で括弧がほとんど減らなかった（2,479 → 2,466）。

### 7. 事実が変わっていないか照合する

```bash
python scripts/check_facts.py --base <git ref> <ファイル...>
python scripts/check_facts.py --before <元のファイル> <直したファイル>
```

書き換え前と書き換え後で、コードブロックの中身、バッククォート内の識別子、数値、「」で囲んだ語の集合を比べる。消えたものと増えたものが出たら、1件ずつ原因を確かめる。地の文のカタカナ語（3字以上）と英字の語は、書き換え後に1回も出てこないものを「言い換えの候補」として出す。候補は終了コードに影響しない。「デプロイ」を「配る」にしたような独自の言い換えは、元の語に戻す。「コードブロック」を「コードのブロック」にしたような、複合語を分けただけのものはそのままでよい。重複していた文を削ったなど説明がつけばよい。説明がつかなければ戻す。書き換えた文で打ち消し（「ない」「ません」）や確信の度合いの語（「必ず」「かもしれ」など）が増減したものも、候補として前後の文を並べて出す。肯定と否定や言い切りの強さが変わっていたら戻す。打ち消しを肯定形に言い換えただけなら、そのままでよい。

スクリプトでは、確信の度合いの変化（「相談する」が「合意した」になる等）、見出しで落ちた条件、補った主語、足した接続の言葉、言い換えで足した条件や様子（「あらかじめ」「必要なら」「少しずつ」など）は拾えない。`do-not-change.md` §7に沿って、変えた箇所を元の文と並べて目で確かめる。

### 8. 報告する

- 手順3と6の数値の比較、手順7で残った差分とその理由、対象から外したファイルを書く
- `japanese-basics.md` のR1〜R5の問いに「いいえ」と答えた文と、その節の箇条書きの規則に当たった文を、Rの番号ごとに挙げる。文ごとに、直したか残したかと、残したならその理由を書く。引っかかった文が無いRは「該当なし」と書く。この欄が書けないなら、問いを当てていないので、手順5に戻る
- 比喩などを読み方を決めて直した箇所は、どう読んだかを添える
- ジャンルとして意図的に残した語り口があれば書く

## 新しく書く文章に当てる

新しく文章を書くときも、このスキルの規範で書ける。使うのは手順の一部だけでよい。

1. 書く前に `genres.md` でジャンルを決め、`japanese-basics.md` と `surface-patterns.md` を読む。業務文書・技術文書・メールなら `structure-patterns.md` も読む。
2. 書く材料は渡された資料と出典を示せる事実に限る。材料が足りなければ想像で補わず、足りないものを書き手に伝える。
3. 書き終えたら `scripts/measure_style.py` で数え、手順6の目標に収める。
4. 見本の了承と事実の照合は行わない。代わりに、素材にない事実・数値を書いていないかを確かめる。

## Gotchas

- **書き手の声を均さない**。エッセイや記事の語り口、引用した話し言葉、敬語の度合い、表記の癖は、読み手が意味を取れる限り残す。そろえてしまうと、書き手の顔が見えない文章になる。
- **「AI っぽさを消した」ことを本文に書かない**。改訂注記・脚注・コメントにも残さない。
- **画面文言・メニュー名・エラーメッセージ・引用は、不自然に見えても直さない**。読み手が画面や原文で探せなくなる。
- **太字を機械的に全部消さない**。業務文書と技術文書では、操作を誤ると処理が止まる注意、取り違えやすい否定には残す。当たる箇所がなければ0でよい。
- **読点は迷ったら打たない**。打たないと読み誤る所にだけ打つ。打つときは、文のいちばん大きい切れ目から順に打つ。短い主語のあとや、主語と述語のあいだには打たない。足す前に、語順を直すか文を分ければ要らなくならないかを見る（`surface-patterns.md` §11）。
- **括弧を機械的に消さない**。名前や場所の特定、略語の初出に使っている括弧は残す。
- **硬い漢語に置き換えない**。癖を消そうとして「使う」を「使用する」に、「広がる」を「拡大を見せる」にすると、今度はそれが不自然になる。
- **連続する空行をまとめる処理を、ファイル全体へ一括でかけない**。コードブロック内の空行まで消える。
- **一文一行の整形はしない**。書籍原稿の慣習で、ほかのジャンルでは表や箇条書きの体裁が崩れる。
