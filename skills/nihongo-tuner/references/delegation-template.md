# サブエージェントへの依頼文の雛形

複数ファイルを並列に書き換えるときに使う。`{}` の部分を埋めて渡す。

## 分担の決まり

- 1ファイルを担当するのは1エージェントだけにする。担当ファイルを依頼文に列挙し、それ以外は触らないと書く。
- 担当エージェントが、さらに子エージェントへ分担することを禁止する（孫の作業が親の完了後も続き、次の担当と同じファイルを同時に書き換える事故が起きた）。
- 途中で止まった担当のファイルを別の担当に渡すときは、前の担当が完了通知を返していることと、ファイルの更新時刻が止まっていることを確かめてから渡す。
- 1エージェントあたり5〜8本、合計3,000行程度までを目安にする。

## 依頼文

```text
あなたの仕事: 次のファイルを、日本語のしくみを踏まえた読みやすく自然な文章に整えること。AI が書いた文章の癖も取り除く。
ファイルを直接 Edit してよい（書き換えが仕事）。日本語で作業する。
担当ファイル以外は触らない。git 操作はしない。自分でさらにサブエージェントを起動しない。

## 担当ファイル
{ファイルの絶対パスを 1 行ずつ}

## ジャンルと文末
{業務文書・技術文書・記事・エッセイ・メールのどれか、文末、意図して残す語り口。ファイルごとに指定}

## 手順
1. 次のファイルを読む（直し方の基準）
   - {スキルのパス}/references/japanese-basics.md
   - {スキルのパス}/references/genres.md
   - {スキルのパス}/references/surface-patterns.md
   - {スキルのパス}/references/structure-patterns.md
   - {スキルのパス}/references/do-not-change.md
2. 担当ファイルを 1 本ずつ Read し、節ごとに Edit する。ファイル全体を Write で作り直さない
3. 文の組み立てと語の選び方を直す。japanese-basics.md の R1〜R8 の問いを、R1 から順に 1 文ずつ当てる。問いに「いいえ」と答えた文と、その節の箇条書きの規則に当たった文は、直したか残したかを控えておく（報告に使う）
4. 表面の癖を直す（太字は 1 節に 1〜2 箇所まで、括弧の補足、ダッシュ、決め台詞と予告、重複した注意、社内の言い回し、絵文字、文末の混在）
5. 組み立てを直す。ジャンルが許す範囲で（注意は「やってはいけないこと → 理由 → 例外」、手順は「何をするか → 手順 → 補足」、仕様は「何が起きるか → 条件」。1 段落に場所・条件・結果・例外が 3 つ以上あればラベル付きで分ける）
6. 終わったら次を実行し、出力された差分を 1 件ずつ確認する。説明のつかない差分は戻す
   python {スキルのパス}/scripts/check_facts.py --base {git ref} {担当ファイル}
   git でなければ、ファイルごとに --before {元のファイル} {直したファイル} を使う
   「[候補] 言い換えの候補」は差分ではない。独自に言い換えた語だけを元の語に戻し、複合語を分けただけのものはそのままにする

## 了承済みの見本（この直し方に合わせる）
{SKILL.md の手順 4 で了承を得た修正前後の例をそのまま貼る}

## 目標値（measure_style.py で確認する）
- 文の括弧（表の外で、中身が文になっている括弧）: 各ファイル 0〜2
- 太字過多の節（表の外で太字が 3 つ以上ある節）: 0
- 決め台詞・空句・社内語・絵文字・ダッシュ・冗長: 0（残すなら報告に理由を書く）
- 句点の落ちた項目（文になっているのに句点で終わらない箇条書きの項目）: 0
- 読点過多文・読点が細かい文・短い文の主語読点: 業務文書と技術文書は 0。同じ語が続いて読みにくくなる所の読点は残してよい（残したら報告に理由を書く）。記事とエッセイでは件数を目標にせず、見直す文を拾う目安にする
- 英数字の前後の空白: 0。書き手や媒体の表記の決まりで入れているときは数えない

## 変えてはいけないもの
コードブロックの中身（空行を含む）、バッククォート内の識別子、数値、「」で囲んだ画面文言・メニュー名、技術的な挙動の記述、【要確認】の印と本文、見出しの階層と番号（見出しの中の社内語は直してよい）。

## 足してはいけないもの
元の文にない条件・理由・様子・程度・時期、動作をする人、接続詞。意味が 1 通りに決まらない語・比喩・標語は、読み方を選んで書き換えず、元の語のまま残して報告に候補を書く。

## 報告
1. 要約（500 字以内）：ファイルごとの主な直し、check_facts.py で残った差分とその理由、判断に迷った箇所。
2. 点検の結果（字数の上限なし。省かずに全件書く）：R1〜R5 の問いに「いいえ」と答えた文と、その節の箇条書きの規則に当たった文を、ファイルごと・R の番号ごとに挙げ、直したか残したか（残したなら理由）を書く。引っかかった文が無い R は「該当なし」と書く。比喩などを読み方を決めて直した箇所は、読み方の候補を添える。目標に届かず残した指標は、その理由を書く。
```
